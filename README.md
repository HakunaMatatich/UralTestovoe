# Подбор автозапчастей

Клиентское приложение на React для интеграции с веб-сервисом «Проценка» Favorit Parts. Интерфейс реализует двухэтапный подбор номенклатуры: сначала поиск производителей по артикулу, затем получение аналогов и предложений по выбранному бренду.

Документация API: [https://lk.favorit-parts.ru/static/wsprice.pdf](https://lk.favorit-parts.ru/static/wsprice.pdf)

## Что добавлено

Поверх шаблона Vite + React собрано рабочее приложение поиска запчастей:

- двухэтапный сценарий: артикул → список брендов → таблица аналогов;
- состояние приложения в Redux (загрузка, ошибки, выбранный бренд, результаты);
- запросы к Favorit Parts через прокси Vite (`/hsprice` → `http://api.favorit-parts.ru/hs/hsprice/`);
- обработка пустого ответа API, сбоев сети и ошибок вида `{ error: "..." }`;
- индикаторы загрузки и сообщения об ошибках;
- интерфейс на Bootstrap.

Основные файлы:

## Зависимости

Установка:

```bash
npm install
```

Основные пакеты:

- **react**, **react-dom** — UI;
- **@reduxjs/toolkit**, **react-redux** — состояние и асинхронные запросы;
- **bootstrap** — стили и сетка.

Сборка и разработка: **vite**, **@vitejs/plugin-react**, ESLint.

TypeScript не используется.

## Запуск

```bash
npm run dev
```

Приложение открывается на [http://localhost:5173/](http://localhost:5173/).

Другие команды:

```bash
npm run build    # production-сборка
npm run preview  # просмотр сборки (прокси тоже включён)
npm run lint     # проверка кода
```

Ключ API — тестовый ключ покупателя Favorit. Свой ключ можно задать в `.env`:

```
VITE_FAVORIT_KEY=ваш-ключ
```

Без `.env` используется ключ из документации Favorit.

## Основные разделы приложения

1. **Шапка** — название и краткое описание сервиса.
2. **Этап 1. Поиск производителей** — поле артикула и кнопка «Найти производителей».
3. **Производители** — список брендов по введённому номеру. У каждой позиции: название бренда, пример наименования детали, суммарный остаток.
4. **Этап 2. Аналоги и предложения** — таблица после выбора бренда:
   - название и производитель;
   - артикул;
   - стоимость (минимальная цена среди складов, как требует API);
   - остаток на складах;
   - тип: «Искомая» или «Аналог».

## Как работает приложение

Пользователь вводит артикул и отправляет форму. Redux thunk `fetchBrands` делает GET без бренда:

`/hsprice/?key=...&number=01089`

Из массива `goods` собирается уникальный список производителей. Если товар не найден (пустая структура в `goods`) или запрос упал, показывается предупреждение или ошибка.

После клика по бренду thunk `fetchOffers` повторяет запрос уже с производителем и аналогами:

`/hsprice/?key=...&number=01089&brand=ASAM&analogues=on`

Искомая позиция и вложенный массив `analogues` выводятся одной таблицей. Цена берётся из `warehouses[].price`, а не из устаревшего поля `goods.price`. Пока идёт запрос, кнопки брендов блокируются и показывается лоадер.

Пример проверки:

1. Артикул `01089` → список брендов (ASAM, FEBI и др.).
2. Бренд `ASAM` → искомый фильтр и аналоги с ценой и остатком.
3. Несуществующий артикул, например `7260500039S` → «производители не найдены».
